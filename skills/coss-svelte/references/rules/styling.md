# Styling Rules

- Use the coss-svelte theme and semantic CSS variables; do not hard-code light-only colors.
- Keep product UI compact, readable, and dense in the COSS style.
- Prefer existing component variants and parts before adding one-off utility stacks.
- Use Tailwind CSS 4 conventions and the local theme contract from `@coss-svelte/theme/style-coss.css`.
- Icons should be real icon components from the project's icon library when available.
- Avoid decorative gradients, oversized marketing hero patterns, and nested cards inside cards for operational UI.
- Preserve focus-visible states, disabled states, invalid states, hover states, and reduced-motion behavior.
